**Troida** - фреймворк для алгоритмической торговли на финансовых рынках.

## Навигация.
1. [backtesting](backtesting) - каркас проекта, включающий вспомогательные программы, такие как:
- для парсинга данных - [historical_data_parsing.py](backtesting/historical_data_parsing.py) (требуется переделать);
- для доступа к данным - [historical_data_access.py](backtesting/historical_data_access.py).

> Доступны функции получения типа тикера, полного пути файла с историческими данными, возвращения данных в определённом формате.
- оптимизация стратегии - [optimization.py](backtesting/optimization.py);
- шаблон стратегии - [strategy_template.py](backtesting/strategy_template.py);
- визуализация результатов стратегии - [backtesting/strategy_visualization.py](backtesting/strategy_visualization.py);
- список тикеров - [tickers.py](backtesting/tickers.py).

2. [historical_data](historical_data) - хранилище исторических данных в формате historical_data/<ТИП АКТИВА>/<ТИКЕР>/<ТИКЕР_ПЕРИОД_ДАТАНАЧАЛА_ДАТАКОНЦА>.csv.

3. [strategies](strategies) - хранилище стратегий.

4. [documentation](documentation) - база знаний. Тут хранятся статьи в формате markdown (текстовые файлы, но с **оформлением**).
> Для удобства установите программу Obsidian, выберите ```documentation``` как путь к хранилищу. В настройках зайдите в Files and links -> Attachment folder path и напишите туда _mediafiles.

5. [requirements.txt](requirements.txt) - файл с библиотеками. Для установки требуется прописать: ```pip install -r requirements.txt```.

## Рекомендации по разработке  
1. **Соблюдайте стандарт PEP 8**.  Придерживайтесь [официального руководства PEP 8](https://pythonworld.ru/osnovy/pep-8-rukovodstvo-po-napisaniyu-koda-na-python.html). Это обеспечит читаемость и единообразие кода в команде.  
2. **Изучайте документацию библиотек**.  Перед реализацией функционала проверьте документацию (например, Backtrader). В большинстве случаев необходимые инструменты уже существуют в библиотеке.  
3. **Используйте существующие решения**. Если задача решается стандартными классами или функциями, применяйте их вместо создания собственных костылей.  
4. **Декомпозируйте сложные задачи**. Разбивайте крупные задачи на модули, классы и функции. Если часть кода может быть полезна в других проектах, проектируйте её как переиспользуемый компонент.  
5. **Документируйте код**. Комментируйте сложные функции и формулы, но избегайте избыточного пояснения для очевидных фрагментов.  
6. **Формулируйте осмысленные коммиты**. Описывайте изменения кратко, но информативно. Избегайте как излишне подробных, так и неинформативных сообщений.
